# Cash Flow

Self-hosted личная финансовая аналитика для **мультивалютных** банков (Revolut,
PKO BP и др. через [Enable Banking](https://enablebanking.com)). Свой маленький бэкенд
на Node + SQLite и дашборд в стиле Revolut с честной конвертацией валют по курсу НБП
на дату каждой операции.

Без Docker: один нативный процесс под launchd, одна база SQLite. Наружу уходят только
запросы к банкам (через Enable Banking) и к публичному API курсов НБП.

> ⚠️ Проект не связан с Revolut, PKO BP или Enable Banking.
> Это личный pet-project, а не финансовый совет. Используйте на свой риск.

---

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Сервер | `dashboard/server` | HTTP API на :5055, https :5443 для колбэка банка, синк, бэкапы. **Ноль npm-зависимостей** (встроенный `node:sqlite`). |
| База | `data/cashflow.sqlite` | Счета, операции (суммы в минорных единицах), категории, правила, настройки. |
| Фронтенд | `dashboard/web` | React 19 + TypeScript + Vite + Radix Themes + recharts + Biome, FSD-структура. |
| Автозапуск | `~/Library/LaunchAgents/com.cashflow.server.plist` | Стартует при входе в систему, перезапускается при падении. |

Модули сервера: `db.mjs` (схема и миграции), `eb.mjs` (клиент Enable Banking и
нормализация операций), `sync.mjs` (синк и привязка банков), `rules.mjs` (правила
категоризации), `fx.mjs` (курсы НБП), `backup.mjs` (снапшоты в iCloud).

### Возможности

- Сводка за месяц / период: доход, расход, net, норма сбережений, дельты к прошлому
  периоду, график накопленного net и трат по дням (с разбивкой «на что» и операциями дня).
- Категории с раскрытием до мерчантов; мерчанты в разных валютах не слипаются.
- **Мультивалютность**: валюта — свойство счёта (у банковских приходит из банка), суммы
  хранятся в валюте счёта, пересчёт в PLN/USD/EUR/CHF по кросс-курсу НБП на дату.
- Правка из UI: категория с охватом (одна / период / вся история + правило на будущее),
  «исключить из аналитики», получатель и заметка; у ручных операций — дата, сумма, удаление.
- Категории: создание прямо из выпадающего списка, переименование, удаление со слиянием
  (операции и правила переезжают в другую категорию).
- Правила: список с поиском и числом совпадений в истории, добавление, смена категории,
  «применить к операциям без категории».
- **«Капитал»**: балансы всех счетов, история капитала, структура, история счёта,
  ручные операции и переводы между счетами.
- **«Банки»**: срок согласия PSD2, баланс по данным банка, статус синка каждого счёта,
  переподключение в один клик.

## Требования

- macOS, **Node.js ≥ 22.16** (встроенный `node:sqlite`; проверено на 22.20).
- Аккаунт Enable Banking ([enablebanking.com](https://enablebanking.com)) — бесплатный
  restricted mode для личного использования.

## Установка

```bash
git clone <this-repo> cash-flow && cd cash-flow
cp .env.example .env && chmod 600 .env    # заполнить EB_APP_ID / EB_KEY_FILE
./cashflow.sh install                     # соберёт фронт, поставит launchd-агент, запустит
```

Дашборд — **http://localhost:5055**. Проект держите вне `~/Documents`, `~/Desktop` и
`~/Downloads`: фоновые процессы macOS туда не пускает.

### Управление

```bash
./cashflow.sh status          # агент, последний синк, сроки согласий
./cashflow.sh start | stop | restart
./cashflow.sh logs            # лог сервера (data/logs/server.log)
./cashflow.sh build           # пересобрать фронтенд (рестарт не нужен)
./cashflow.sh dev             # Vite :5173 с hot-reload поверх сервера :5055
./cashflow.sh sync            # банк-синк сейчас
./cashflow.sh backup [--full] # снапшот в iCloud (см. ниже)
./cashflow.sh uninstall       # убрать агент (данные остаются)
```

## Банки (Enable Banking)

1. **[один раз, вручную]** На [enablebanking.com](https://enablebanking.com/cp/applications)
   создайте приложение (**Production**), redirect URL:
   `https://localhost:5443/enablebanking/auth_callback`. Сгенерируйте ключ — скачается
   `<app-id>.pem`; положите его в `secrets/` (`chmod 600`) и пропишите в `.env`
   `EB_APP_ID` и `EB_KEY_FILE`. Активируйте приложение, привязав свои счета (restricted mode).
2. В дашборде → **«Банки»** → «Подключить банк» → авторизация в банке. Браузер один раз
   спросит про самоподписанный сертификат `https://localhost:5443` — это наш сервер.
3. Счета создадутся сами (с остатком на дату привязки), дальше синк — по расписанию
   (`AUTO_SYNC_TIMES`, по умолчанию 07:30; после сна ноутбука догоняет) и кнопкой «↻ Обновить».

**Согласие PSD2** берётся на максимум, который даёт банк (Revolut и PKO — 180 дней).
За 14 дней до конца в шапке появится «⚠ согласие: N дн.». Переподключение — кнопка
на странице «Банки»: счета перепривязываются автоматически по `identification_hash`
(запасной вариант — IBAN + валюта), история не трогается.

Как работает синк: окно запроса — последние 14 дней от последней проведённой операции
(не дальше 89 дней), дедупликация по id операции в банке. Операции «в обработке»
(pending) импортируются сразу и обновляются, когда банк их проведёт; отменённые
блокировки удаляются. Новые операции категоризируются правилами. Ручные правки
(категория, получатель, заметка) синк не перезаписывает.

## Настройки (⚙ в шапке)

- **Группа исключений** — группа категорий, не участвующая в cash flow (переводы между
  своими счетами, обмены валют, отменённые платежи). По умолчанию «Переводы и обмены».
- **Категория для «Исключить из аналитики»** и **для переводов между счетами**.
- **Категории** и **правила** — см. «Возможности».

Иконки/цвета категорий — `dashboard/web/src/shared/config/categories.ts`.

## Разработка

```bash
./cashflow.sh dev                         # фронт с hot-reload; API — живой сервер :5055
./cashflow.sh restart                     # после правок в dashboard/server
npx --prefix dashboard/web biome check dashboard/web/src
```

Схема базы — массив миграций в `dashboard/server/db.mjs` (`PRAGMA user_version`),
только дописывать в конец. Перенос из Actual Budget, с которого проект начинался, —
`dashboard/server/scripts/migrate-actual.mjs` (со сверкой балансов до цента).

## Бэкап и восстановление

- **Код** → git-репозиторий (приватный). `secrets/`, `.env`, `data/`, `personal/` в
  `.gitignore`.
- **База** → после каждого синка сервер кладёт консистентный снапшот (SQLite online
  backup, без остановки) в `ICLOUD_BACKUP_DIR`: `cashflow-<дата>.sqlite.gz`, хранятся
  последние `BACKUP_KEEP`.
- **Полный бандл** (база + `.env` + `secrets/` + `personal/`) — вручную после смены
  секретов или конфига: `./cashflow.sh backup --full` → `cashflow-full-<дата>.tgz`.
  Секреты при этом уходят в iCloud — осознанный компромисс ради восстановления в один шаг.

Пошагово — **[RESTORE.md](RESTORE.md)**.

> ⚠️ Живую SQLite нельзя синкать облаком напрямую (WAL + дозапись = битая копия),
> поэтому в облако едет снапшот, а не рабочая папка `data/`.

## Приватность

Данные хранятся локально. Наружу: банковский синк через Enable Banking и запросы курсов
к публичному API НБП. Секреты — только в `.env` (600) и `secrets/`.
